# S5 预先冻结的验收计划

在开始 S5 性能采样前固定三组测试 seed：0123456789abcdef、fedcba9876543210、6a09e667f3bcc909。生产默认使用 SecureRandom；最终交付另做无测试 seed 的构建和设备验证，不把统一测试 seed 带入默认路径。

原基线为 14bc959 的完整源码快照，保存在 build/on-demand-20260912/baseline-14bc959/；仅允许用于固定测试随机参数的补丁，原 VM/loader 运行语义冻结。新模式使用本轮完成的 S1–S4/P5。两边使用同一指定 APK、规则、mapping、原证书、ARM64/API26 编译目标、NDK26.3、O-MVLL1.8 和同一配置。

A=原 legacy/loader OFF；B=原 legacy/loader ON；C=按需+native VM/loader OFF；D=按需+native VM/loader ON（stage0 VM ON）。每组内尽可能共享原 opcode 置换和构建参数；记录仍不可控的构建随机来源，不声称二进制可复现。

启动按 ACCEPTANCE：3 次预热、20 次有效进程冷启动，各配置交错覆盖安装；保留用户数据，检查旧 PID 退出、当前 PID 主窗口首绘与 resumed、异常、APK身份。报告 ThisTime 中位数/P95、D/A、B/A、D/C，不用 layer-by-layer 的 10% 相加。窗口观察时间仅作上界证据。

热点使用同一 DEX 方法经真实生产生成器转换的独立 ART harness，覆盖计算/分支循环、短方法高频调用、大方法短路径，以及 JNI/对象调用；它是补充性能证据，不替代指定业务 APK。各方法结果保持可观察，正式采样关闭逐指令日志和计数探针。尽量按 5 轮预热、20 轮、双方相同迭代数且单轮至少约 1 秒执行。任何未满足的规程必须单列，不能当作通过。

API27 为当前可用设备；API26 和需要实际激活/服务端的业务路径保持明确缺口。若任一热点或启动超过总计 10%，保留实验模式并定位瓶颈，不启用明文缓存、不减少选中方法、不关闭绑定。

正式热点计时前的补充（尚未采样）：输入固定为 8 个 native 方法、9 个场景，补齐 array payload、异常、递归及四线程 shortCall。大方法 DEX 为 7896 字节、array payload 为 512 字节，输入摘要保留。每场景按平衡正反两批执行，每批每变体 5 次预热＋10 次测量，总计每变体 10 次预热＋20 个有效样本；迭代数按校准中最快变体约 1.5 秒预先选定，两版保持相同，过短样本明确标识，不当通过。每线程 iterations，多线程总调用数为 4×iterations，建线程/join 含在计时内。45 个纯 Java 驱动总和回验通过；实际 ART 每轮另核对独立期望值。单轮无输出 600 秒会终止驱动并报告失败。

分配/读取探针仅在复制出来的 A/C（private OFF）库中启用：链接包装 malloc/calloc/realloc/free，VmReader 副本逐字节计数及密钥流块 miss、最大偏移。它们不用于正式计时；native 请求数不等于 ART 分配数、存活字节或泄漏证明，读取次数含重复访问且不覆盖记录/初始化扫描。正式 JAR 与运行库不包含探针。

首次三组启动采样后观察到明显时间双峰。按 ACCEPTANCE §6.4，预先追加每个相同 seed 各一个独立的3次预热/20次测量批次，保留所有批次；配对比率和敏感性计算只作诊断，不替代边际中位数门槛，也不作为删样本依据。

largeShort 校准发现旧模式每轮预计695–712秒，超过原采集器600秒看门狗；严格三seed约需35小时。第一组在该场景预热期间停止，保留前八个场景和校准结果；后两组先执行其余八项，计划中仍保留全部九项，未测项不判完成。严格延长采集还是缩短并列时长缺口的偏好问题已提交用户，尚未改变该场景的验收门槛或接受任何正式样本。

偏好问题等待期间未收到回复，继续独立工作后决定先做同为10000次调用的largeShort有限时长诊断。它仍取两批各5预热/10测量，明确保留快版本单轮不足1秒的规程缺口，不当作正式通过，不放宽10%门槛，也不声称这是用户已批准的选择。严格采样计划保留；看门狗修正为600秒与校准最慢版本预计单轮三倍中的较大值，避免把已预测的正常长耗时误判成无响应。

## 最终审查追加记录

三组S5库冻结后，合同复核发现显式解码暂存未全部可靠擦除；补齐固定80字节 `VmDecodedState` 和独立 FETCH word 清理。这是功能正确性修复，不是为改变性能结论而挑选优化。旧库、旧JAR/APK与原始样本保持不变。

修复后重新同步模板、构建JAR及原签名的完整增强/默认legacy APK，继续526方法回验、ARM64 Debug/Release按需与legacy语义、实际退出清理/递归/八线程验证。性能追加固定seed1的算术、分支、短调用对照，每配置两批各5次预热/10次测量：A原始legacy OFF，C冻结的修复前增强private ON，D修复后增强private ON；相同迭代数，保留所有样本。该定向验证不冒充修复后完整三组九场景验收。最终候选覆盖安装并作短期驻留观察，保留应用数据。

冻结seed1独立启动批在D第10轮读取电池时本机ADB连接超时，窗口/READY/resumed此前通过；后续仍为同一应用PID与原ADB服务PID。保留43个有效样本及无效记录，在新的续采目录从该轮继续。续采是同一独立批次的延续，不再计作额外独立批次。
